# 家庭无情裁判所 数据库表结构初稿

## 1. 文档目标

本文档定义云端模式下第一阶段的 PostgreSQL 数据模型草案，主要服务于：

- `Prisma schema` 建模
- NestJS 模块拆分
- API 字段约定
- 事件、排行、归档、AI 判决的数据边界

说明：

- 本文档只覆盖 `云端模式`
- 单机模式主真相源仍为 `Dexie / IndexedDB`
- 命名以 `PostgreSQL + Prisma` 风格为准

## 2. 建模原则

### 2.1 事实表优先

`task_events` 是系统核心事实表。  
所有排行、日志、周归档、AI 判决都应基于它推导或快照。

### 2.2 历史不可回写

成员名、任务标签、分类、分值在事件发生时必须保存快照。  
后续规则修改不能影响旧事件的历史解释。

### 2.3 真相源唯一

- 云端模式：`PostgreSQL`
- 缓存/会话/临时窗口：`Redis`

### 2.4 先稳后复杂

第一阶段不引入过多中间聚合表。  
优先使用：

- 事实表
- 少量配置表
- 周归档快照表
- AI 结果表

## 5. 表结构草案

## 5.1 `family_accounts`

统一账号表。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `uuid` | PK | 账号 ID |
| `account_name` | `varchar(50)` | unique, not null | 家庭统一账号 |
| `password_hash` | `varchar(255)` | not null | 密码哈希 |
| `password_algo` | `varchar(30)` | not null | 哈希算法标记 |
| `status` | `varchar(20)` | not null, default `ACTIVE` | 账号状态 |
| `last_login_at` | `timestamptz` | null | 最近登录时间 |
| `created_at` | `timestamptz` | not null | 创建时间 |
| `updated_at` | `timestamptz` | not null | 更新时间 |

索引建议：

- unique(`account_name`)
- index(`created_at`)

## 5.2 `families`

家庭空间主体表。

| 字段 | 类型 | 约束 | 说明 |

| `created_at` | `timestamptz` | not null | 创建时间 |

## 7. Redis 使用建议

Redis 不做主数据存储，只承载临时状态：

- 登录态 / refresh token 黑名单
- 撤销窗口状态
- 当前周排行快照缓存
- SSE 连接辅助状态
- 高频查询缓存

建议 key 设计：

- `session:{familyId}:{sessionId}`
- `undo:{familyId}:{eventId}`
- `rank:{familyId}:{weekId}`
- `sse:{familyId}:subscribers`

## 8. Prisma 模型命名建议

Prisma 建议采用 PascalCase：

- `FamilyAccount`
- `Family`
- `FamilySession`
- `Member`
- `TaskRule`
- `TaskEvent`
- `WeeklyArchive`
- `VerdictRecord`
- `Preference`
- `AuditLog`

数据库表建议显式映射为 snake_case：

```prisma
model TaskEvent {
  @@map("task_events")
}
```

## 9. 第一阶段可延后字段

以下字段若开发压力较大，可在第一阶段先简化：

- `avatar_url`
- `audit_logs.before_json / after_json`
- `verdict_records.safety_status`
- `family_sessions.user_agent`

但以下字段不建议删：

- `client_event_id`
- `undo_token`
- `undo_expires_at`
- `status`
- 各类 snapshot 字段

## 10. 最终结论

第一阶段数据库设计应以以下结构为核心：

1. `task_events` 作为唯一事实表
2. `weekly_archives` 作为周级快照
3. `verdict_records` 作为 AI 结果存档
4. `preferences` 承载控制台风格与公共屏偏好
5. `audit_logs` 承载高风险操作审计

后续若要进入实际开发，建议下一步直接据此产出：

- `schema.prisma` 初稿
- NestJS 模块目录草案
- 种子数据结构
