### 1.4 术语定义

| 术语 | 定义 |
| --- | --- |
| 单机隐私版 | 数据仅保存在当前设备浏览器本地，不联网、不上传，不提供 AI 判决与跨设备同步能力。 |
| 云端 AI 版 | 使用家庭统一账号登录，支持云端存储和 AI 判决，可扩展多设备查看能力。 |
| 举手之劳 | 1 分级轻量家务，通常耗时短、频次高，如倒垃圾、拿快递、擦桌子。 |
| 核心家务 | 3 分级中等负担家务，通常需要连续投入，如洗碗、扫拖地、晾衣服。 |
| 史诗恶战 | 5 分级高消耗家务，通常情绪和体力投入都明显，如做饭、辅导作业、刷马桶。 |
| 公开日志 | 底部实时滚动的操作记录区，用幽默方式公示谁在何时完成了什么家务，本质是可追溯操作日志。 |
| 咸鱼徽章 | 排行榜末位成员的视觉标记，用于制造吐槽或公开处刑氛围；具体是否走向羞辱化表达由控制台风格配置决定。 |
| 家庭统一账号 | 一个家庭共用的唯一账号，用于登录、设置、结算、删除等所有操作；产品内所有操作均基于这一账号完成，不做成员分权设计。 |
| 家庭判决书 | 周末由 AI 生成的总结文案，包含数据总览、冠军表彰、垫底调侃、奖惩建议和暖心结语。 |
| 家庭控制台 | 主打卡界面之外的统一配置与查询中心，用于管理成员、家务标签、历史记录、周报档案和全局偏好。 |
| 沉寂状态 | 当成员超过设定时长没有任何有效打卡动作时，角色卡片进入轻量变暗或附着幽默特效的提醒状态，完成一次有效打卡后恢复正常。 |
| 数据分析页 | 控制台中的独立页签，用于查看家庭整体趋势、成员公平性对比和系统自动结论摘要。 |
| 系统结论摘要 | 基于固定规则和统计指标自动生成的分析结论，用于数据分析页；不由 AI 生成。 |

## 2. 产品概述

### 2.1 产品背景与痛点

在现代家庭关系中，真正让人积累委屈的，往往不是“大扫除”这种显性劳动，而是那些每天都在发生、却很难被完整记住的隐形家务。围绕“到底是谁干得更多”的讨论，常常在缺乏客观数据的情况下迅速滑向情绪对撞。

本产品要解决的不是“如何把家务管理得像公司流程”，而是提供一个足够轻、足够快、足够有趣的公共空间工具，让隐形付出被看见，让争论少一点主观记忆，多一点轻松、透明和可复盘。

### 2.2 产品定位与核心价值

「家庭无情裁判所」是一款基于数据可视化与 LLM 的家庭情绪管理与家务结算中枢，终端形态为摆放在家庭公共空间的横屏 Web 面板。

核心价值如下：

1. **让隐形家务被看见。** 用极简打卡把琐碎付出变成可累积、可回顾的数据。
2. **让争吵有客观依据。** 用实时排行榜和公开日志降低“我明明做过”的争执。
3. **让结算更像调解，而不是清算。** 用“毒舌但暖心”的 AI 判决，把家务争论从对人指责转成对事复盘。
4. **让公共空间本身变成家庭仪式感的一部分。** 设备常亮、随手可点、周末可结算，形成低成本但高存在感的家庭协作反馈回路。

产品体验原则如下：

1. **一眼看懂：** 所有人站在 1 米外也能知道谁领先、谁垫底。
2. **两步完成：** 常见打卡必须在 2 步内完成，不需要层层进入二级页面。
3. **风格可放开：** 所有文案允许吐槽、攻击、羞辱和贴标签，不做统一内容限制；具体风格强度与口吻由控制台统一调整。
4. **规则可调整：** 不同家庭对“什么算家务”有差异，系统要支持轻量自定义。

### 2.3 产品目标（OKR）

| 目标 | 关键结果（KR） | 衡量方式 |
| --- | --- | --- |
| O1：降低家庭家务争吵频次 | 用户反馈家务争吵次数减少 ≥ 60% | 以家庭统一账号主要使用者每 4 周一次的问卷回访为主，辅以产品内简短反馈入口 |
| O2：提升家务记录便捷性 | 单次打卡操作控制在 2 步内完成，整体体验足够轻快；活跃家庭成员日均打卡率 ≥ 80% | 通过操作时长埋点、周活跃打卡日志统计或本地周报统计 |
| O3：强化 AI 判决的趣味性与实用性 | 用户对 AI 判决书满意度 ≥ 90%；奖励 / 惩罚建议实际落地率 ≥ 70% | 通过判决书后的单击满意度反馈和管理员周末复盘勾选记录 |

### 2.4 目标用户画像

| 用户角色 | 核心特征 | 主要诉求 |
| --- | --- | --- |
| 家庭发起人 | 25-45 岁已婚 / 同居人群，数字产品接受度中等，希望减少“谁做得多”的重复争论 | 快速建档、方便改规则、可回顾历史、整体流程足够省心 |
| 成人家庭成员 | 家务参与频繁，希望自己的劳动被看见，但不愿意花时间维护复杂系统 | 快速打卡、反馈明确、过程有趣，可根据家庭偏好决定是否接受更强烈的审判式吐槽 |
| 有娃家庭成员 | 家中存在 6 岁以上儿童，家长希望培养参与感和责任感 | 规则简单、视觉鲜明、分值直观、文案不过度成人化 |
| 中老年成员 | 对复杂交互不敏感，但能接受“大按钮 + 明确反馈”的设备 | 字大、对比强、动作少、无需记住复杂账号流程 |

### 2.5 典型使用场景

| 场景 | 使用时机 | 用户目标 | 成功结果 |
| --- | --- | --- | --- |
| 日常碎片化打卡 | 做完一项家务、路过设备时 | 迅速记一笔，不打断当前生活节奏 | 在 2 步内完成打卡，排行榜与日志即时更新 |
| 周末集中结算 | 周五晚或周末晚饭后 | 让全家一起看一份有趣又有依据的家务周报 | AI 判决书生成顺畅，奖惩建议可执行 |
| 自定义家庭规则 | 节假日、季节变化、家庭成员状态变化时 | 新增特殊家务标签或调整分类、分值 | 规则修改后前端即时生效，且不破坏历史记录 |

## 3. 核心需求

### 3.1 核心业务流程

| 步骤 | 说明 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| 家庭建档 | 家庭发起人使用家庭统一账号选择单机隐私版或云端 AI 版，创建家庭空间并添加成员 | P0 | 首次启动后 3 分钟内可完成模式选择、成员创建和首页进入 |
| 无感打卡 | 家庭成员完成家务后点击自己的卡片按钮并选择具体事项完成记录 | P0 | 常见打卡动作控制在 2 步内，且可即时看到分数变化 |
| 公开监督展示 | 所有得分动作进入实时排行榜和公开日志 | P0 | 任意一次有效打卡后，排行榜和日志应近实时同步更新 |
| AI 周末结算 | 用户点击按钮生成《家庭判决书》，作为下一周奖惩依据 | P0 | 生成过程应在家庭场景可接受等待范围内完成，失败时可降级到本地模板，不出现空白状态 |
| 归档复盘 | 结算后自动归档本周数据，支持历史查看和规则调整 | P1 | 本周数据成功归档，当前周数据清零，历史可查看最近 12 周 |

### 3.2 初始化与账号模块

| 字段 | 内容 |
| --- | --- |
| 模块优先级 | P0 |
| 模块目标 | 让家庭统一账号操作者以尽可能低的认知成本完成模式选择、账号建立、成员创建和后续维护 |
| 核心角色 | 家庭统一账号操作者 |
| 模块验收标准 | 1. 首次启动流程不超过 4 步。<br>2. 单机隐私版在断网状态下可继续完成本地打卡与历史查看。<br>3. 云端 AI 版可完成极简注册、登录、成员增删与下次自动登录。 |

#### 3.2.1 功能需求

| 功能项 | 需求说明 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| 模式选择 | 首次进入时展示“单机隐私版 / 云端 AI 版”双入口，并明确说明能力差异：单机版仅本地存储、无 AI；云端版支持 AI 和多设备能力。 | P0 | 用户无需阅读长说明，也能区分两种模式差异并做出选择 |
| 单机隐私版数据持久化 | 所有家庭配置、成员信息、本周积分、日志、历史归档存储于 LocalStorage，并带版本号字段。 | P0 | 刷新页面或重启浏览器后，数据仍可恢复；无明文上传行为 |
| LocalStorage 数据防丢失 | 提供“导出备份”按钮，支持导出完整 JSON；当检测到 7 天未备份且已有数据时，提示用户手动备份。 | P0 | 导出文件可被再次导入并完整恢复成员、规则、历史数据 |
| 数据备份 / 恢复 | 支持从本地 JSON 文件恢复；导入前校验版本、字段完整性和成员映射，非法文件给出明确报错。 | P0 | 导入合法文件后数据正确覆盖或合并，非法文件不会污染现有数据 |
| 云端 AI 版注册与登录 | 使用“家庭统一账号 + 密码 + 确认密码”完成注册，并使用“家庭统一账号 + 密码”完成登录；密码长度 6-20 位，不强制复杂度，可使用简单密码（如 `123456`），优先保证创建和登录速度。 | P0 | 用户可在 1 分钟内完成注册并进入首页；注册阶段仅校验账号非空、两次密码一致、密码长度与非法字符，不因密码过于简单而拦截 |
| 记住登录状态 | 云端版默认记住家庭账号，不在前端明文保存密码；本地仅保存经 Web Crypto AES-GCM 加密的登录凭证或刷新令牌，30 天失效。 | P0 | LocalStorage / SessionStorage 中不可检索到明文密码；到期后需重新登录 |
| 成员角色卡片管理 | 支持创建 2-10 名家庭成员，配置昵称、头像、卡片色；昵称需唯一。 | P0 | 创建完成后首页能按成员展示对应卡片；当成员数超过 5 人时，面板仍能通过分页或横向滑动清晰展示 |
| 多设备查看 | 云端版允许同一家庭账号在其他设备登录查看榜单和判决书；支持打卡与设置。 | P1 | 辅助设备登录后可看到同一家庭数据，且不会引发主屏数据错乱；云端版采用 SSE，确保主屏打卡后其他设备可在一秒内无刷新同步最新积分和日志 |


#### 3.2.3 成员角色卡片视觉规范

| 项目 | 规范 |
| --- | --- |
| 颜色体系 | 默认提供 10 组高对比颜色；当成员数大于 6 人时，优先使用扩展色板，避免相邻成员视觉混淆；卡片文字与背景对比度需满足 WCAG AA |
| 昵称规则 | 2-8 个中文字符或 16 个英文字符以内；家庭内唯一；禁止敏感词和纯空格 |
| 头像规则 | 支持上传方形头像图片或使用预设 emoji / 图标；未设置时显示“昵称首字 + 纯色底”占位 |
| 排列规则 | 首页成员列按当前积分排序；控制台成员列表按创建顺序展示，避免因排行变化造成编辑混乱 |

#### 3.2.4 异常场景与处理

| 场景 | 处理逻辑 | 验收标准 |
| --- | --- | --- |
| 云端版忘记密码 | V1 不提供邮箱、手机号、验证码等找回密码链路；用户需自行保管家庭统一账号与密码。控制台仅在已登录状态下提供“修改密码”能力。 | P0：产品不引入额外绑定信息，账号体系保持极简 |
| 单机版本地数据损坏 | 启动时进行 JSON 结构校验；若损坏则提示恢复最近一次导出备份，无法恢复时进入空白初始化页并保留错误说明。 | P0：错误被识别并提示，不出现白屏或卡死 |
| 新增家庭成员 | 新成员以 0 分加入当前周，不继承历史数据；新增后首页即时出现新卡片。 | P0：新增成员后现有成员数据不受影响 |
| 删除家庭成员 | 若该成员当前周已有记录，则标记为“离组”并保留历史；从下一周起不再参与排行榜。无历史记录时可直接删除。 | P0：删除不会误删历史周数据 |

### 3.3 核心打卡面板模块

| 字段 | 内容 |
| --- | --- |
| 模块优先级 | P0 |
| 模块目标 | 用最低认知成本完成家务记录，并通过排行榜和日志即时强化“谁做了什么”的可见性；同时作为家庭公共空间中的默认常驻全屏页面长期展示 |
| 核心角色 | 全体家庭成员 |
| 模块验收标准 | 1. 任意成员完成一次打卡后，页面应快速给出明确视觉反馈。<br>2. 排行榜和日志应近实时更新。<br>3. 多人同时操作不会造成积分丢失、覆盖或错位。<br>4. 支持浏览器全屏模式，进入后优先保留核心打卡信息和大按钮操作区。<br>5. 首页打卡成功后应弹出带撤销入口的 Toast，撤销后积分、日志和排行即时回退。 |

#### 3.3.1 视觉与交互规范

| 元素 | 规范 |
| --- | --- |
| 皇冠徽章 | 主色 #F6C344，位于榜首成员头像右上角；当成员升至第 1 名时触发明显但不过度的强调动画 |
| 咸鱼徽章 | 主色 #7B93A8，位于末位成员头像右上角；当成员跌至最后 1 名时触发轻量提示动画 |
| 排序刷新 | 本地打卡成功后前端立即乐观更新；若有云端确认，以近实时最终结果为准 |
| 头像占位 | 未上传头像时显示圆形占位符，展示昵称首字或首个字母，背景沿用成员卡片主色 |
| 分数跳动 | 总积分需保持足够醒目；点击后触发短促、明确的缩放反馈 |
| 飘分特效 | `+1 / +3 / +5` 分值文本需有向上浮动并淡出的视觉效果；不同档位用不同颜色区分 |
| 按钮反馈 | 按下时需有明显视觉反馈；音效开关可配；触感反馈仅在设备支持且系统未禁用时跟随系统策略 |
| 不同分值按钮区分 | `+1 举手之劳` 采用清爽绿色与轻量图标；`+3 核心家务` 采用蓝色与中性家务图标；`+5 史诗恶战` 采用暖橙或红橙色与更强视觉强调 |
| 公开日志 | 日志滚动速度可在控制台中按快慢档位调节；展示格式为“时间 + 成员 + 具体事项 + 分值 + 家务类型” |
| 全屏模式 | 核心打卡面板支持一键进入和退出浏览器全屏；全屏状态下隐藏非必要浏览器边框，保持排行榜、成员卡片和日志区完整可见 |
| 首页入口区 | 页面右上角固定展示 `控制台`、`全屏`、`召唤 AI 裁判` 三个入口，不使用隐藏长按入口 |
| 标签面板 | 点击家务档位按钮后，以当前成员列附近浮层或底部抽屉形式弹出对应标签面板，只展示该档位可选事项标签 |
| 撤销 Toast | 打卡成功后，屏幕底部或当前成员卡片上方弹出 `打卡成功！[撤销 ↩]` 提示；提示保留 5 秒，期间可撤销本次打卡 |
| 沉寂状态提示 | 当成员超过 48 小时没有任何有效打卡动作时，角色卡片逐步进入沉寂状态，可表现为轻微变暗或附着蜘蛛网 / 蘑菇等幽默特效；完成一次有效打卡后恢复正常 |

#### 3.3.3 首页交互规则

1. 首页长期停留在横屏主打卡面板，默认不跳转到其他页面。
2. 页面右上角固定展示 `控制台`、`全屏`、`召唤 AI 裁判` 三个入口。
3. 用户打卡时先点击自己角色列中的家务档位按钮，再点击具体事项标签完成打卡。
4. 标签面板仅显示当前所选档位下的具体事项，不混合展示其他档位标签。
5. 标签面板应优先展示最近使用和高频标签，减少重复家务的操作成本。
6. 标签点中后立即完成打卡、更新积分、触发飘分动画，并自动关闭面板。
7. 打卡成功后应同步弹出 `打卡成功！[撤销 ↩]` Toast；Toast 保留 5 秒，期间点击撤销则回退本次打卡。
8. 首页撤销机制仅用于首页打卡动作，不替代控制台中的高风险操作二次确认。
9. 首页不直接平铺全部家务标签，避免 10 名成员场景下界面拥挤；具体事项由标签面板承载。
10. 当成员数超过 5 人时，首页允许采用分页或横向滑动展示成员列，但仍需保证每位成员能在 2 步内完成打卡。
11. 若成员长时间没有任何有效打卡动作，角色卡片可进入沉寂状态作为轻量提醒；一旦该成员完成有效打卡，沉寂状态立即解除。

#### 3.3.4 日志规则

1. 日志展示格式为：`14:02 爸爸 完成了 倒垃圾 +1分（举手之劳）`。
2. 屏幕上默认同时展示最近 10 条弹幕式记录，超出后按时间顺序滚动替换。
3. 在首页撤销窗口内被撤销的打卡记录，应同步从日志展示中移除，并回退相关积分和排行状态。
4. 使用统一家庭账号时可手动清空“屏幕展示日志”，但不可因此删除积分事件主数据。
5. 日志导出属于复盘增强功能，研发优先级为 P2。

### 5.4 测试验收重点场景

1. 首次进入后，家庭发起人能在 3 分钟内完成模式选择、成员创建并进入打卡主页。
2. 本地模式断网后，仍能连续完成 20 次打卡，刷新页面后数据不丢失。
3. 用户在首页打卡时，必须通过“点档位 -> 点具体事项标签”两步内完成记录，且日志包含完整标签信息。
4. 首页打卡成功后会弹出 `打卡成功！[撤销 ↩]` Toast；在 5 秒撤销窗口内点击撤销后，积分、日志、排行榜和相关视觉状态会同步回退。
5. 两名成员同时点击不同按钮，最终积分、日志、排行榜均正确。
6. 同一成员快速误触按钮时，不会被重复计分。
7. 家务标签在控制台中被停用后，首页标签面板不再显示该标签，但历史记录仍可查询。
8. 家庭成员扩展到 10 人时，核心打卡面板仍可通过分页或横向滑动清晰完成打卡。
9. 若某成员连续超过 48 小时未发生有效打卡动作，角色卡片会进入沉寂状态；完成一次有效打卡后立即恢复。
10. 进入全屏模式后，排行榜、角色卡片和日志区保持可见，且可一键退出。
11. 控制台可完成成员新增、头像上传、标签配置、打卡历史筛选查询，且返回首页路径清晰。
12. 数据分析页可同时展示家庭整体趋势、成员公平性对比和系统自动结论摘要，默认展示最近 4 周。
13. 同一组分析数据输入时，数据分析页中的系统结论摘要保持稳定一致，不因刷新或重复进入而变化。
14. 云端版主屏打卡后，其他查看设备可通过 SSE 在一秒内无刷新同步积分和日志更新。
15. 云端版不提供邮箱或验证码找回密码；已登录状态下可在控制台修改密码，未登录状态下无额外找回链路。
16. AI 接口超时或断网时，会自动返回本地简版判决，不出现空白结果。
17. AI 输出若为空、结构缺失或前端解析失败，会自动降级为本地简版判决，不出现空白结果。
18. 连续多周使用时，AI 判决书可结合上周结果输出连冠、逆袭、连续垫底等连续叙事。
19. 高风险操作必须经过二次确认，误触不会直接清空数据或停用成员。
20. 归档写入第 13 周数据时，会正确保留最近 12 周并提示备份。

### 5.5 关键风险与缓释策略

| 风险 | 影响 | 缓释策略 |
| --- | --- | --- |
| AI 判决过火，造成成员反感 | 破坏家庭氛围，降低使用意愿 | 强化安全 Prompt、增加内容过滤、允许切换更克制的人设 |
| 本地数据被浏览器清除 | 单机版数据丢失 | 强提醒导出备份，支持导入恢复，必要时提供离线安装包 |
| 公共空间设备被儿童乱点 | 数据失真 | 通过公开日志、误触防抖、首页撤销 Toast 和高风险操作二次确认降低影响 |
| 多设备或多人并发导致数据错乱 | 用户信任下降 | 使用唯一事件 ID、原子写入、待确认 / 正式状态转换和 SSE 最终一致性校验 |
| 页面视觉过于娱乐化，影响长期使用 | 家庭成员容易审美疲劳 | 保留趣味命名，但整体 UI 采用清爽、温和、长期可摆放的家庭风格 |
