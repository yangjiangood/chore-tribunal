# 项目首次拉取与线上更新说明

这份文档用于说明两类事情：

1. 第一次拉取项目后，本地或服务器需要执行哪些命令
2. 线上代码更新、数据库更新、环境变量更新时分别执行什么命令

## 一、项目基础信息

- 包管理器：`pnpm`
- 本地依赖服务：`PostgreSQL`、`Redis`
- 线上部署方式：`docker compose`
- 线上一键部署脚本：`bash deploy.sh`
- 线上一键更新脚本：`bash update.sh`

## 二、本地第一次拉取项目

### 1. 拉取代码

```bash
git clone <你的仓库地址>
cd chore-tribunal
```

### 2. 安装依赖

```bash
corepack enable
pnpm install
```

### 3. 启动本地数据库和 Redis

```bash
docker compose up -d db redis
```

### 4. 准备后端环境变量

如果本地还没有 `apps/backend/.env`，先复制一份：

```bash
cp apps/backend/.env.example apps/backend/.env
```

然后按需修改其中的数据库、Redis、LLM 配置。

### 5. 初始化 Prisma

```bash
pnpm --dir apps/backend db:generate
pnpm --dir apps/backend db:migrate:deploy
```

如果是第一次初始化本地数据，还可以补一份种子数据：

```bash
pnpm --dir apps/backend db:seed
```

### 6. 启动前后端

后端：

```bash
pnpm --dir apps/backend start:dev
```

前端：

```bash
pnpm --dir apps/frontend dev
```

## 三、线上第一次部署

### 1. 拉取代码

```bash
git clone <你的仓库地址>
cd chore-tribunal
```

### 2. 执行一键部署

阿里云服务器和普通 Linux 服务器执行方式一样，直接运行：

```bash
bash deploy.sh aliyun
```

如果你想在第一次部署时直接带上模型 Key，也可以这样：

```bash
DASHSCOPE_API_KEY=你的Key bash deploy.sh aliyun
```

如果你用的是别的提供商，也可以把 `aliyun` 换成：

- `deepseek`
- `kimi`
- `zhipu`
- `custom`

### 3. 首次部署脚本会自动做什么

- 如果不存在 `.env.prod`，会自动创建
- 自动生成 `POSTGRES_PASSWORD`
- 自动生成 `JWT_SECRET`
- 执行 `docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build`

### 4. 首次部署后如果需要初始化种子数据

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml exec backend pnpm db:seed
```

## 四、线上代码有更新时执行什么命令

如果只是线上代码更新，进入项目目录后执行：

```bash
cd /srv/chore-tribunal
bash update.sh
```

这个脚本当前会自动做两件事：

1. 执行 `git pull --ff-only`
2. 执行 `docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build`

也就是说，正常情况下，前端、后端、Nginx 配置变更，都是这一条命令处理。

## 五、线上数据库有更新时执行什么命令

如果本次更新包含 Prisma migration，通常还是执行同一条：

```bash
cd /srv/chore-tribunal
bash update.sh
```

原因是当前后端容器启动命令已经包含：

```bash
pnpm db:migrate:deploy && node dist/src/main.js
```

所以只要 migration 文件已经提交到代码库，容器重建启动时就会自动执行数据库迁移。

### 数据库更新时要注意

- 必须把 Prisma migration 文件一并提交到仓库
- 线上不要执行交互式命令，如 `prisma migrate dev`
- 如果只是普通表结构变更，`bash update.sh` 就够了
- 如果更新里还依赖额外初始化数据，再手动执行一次 seed

例如：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml exec backend pnpm db:seed
```

## 六、线上环境变量有更新时执行什么命令

比如你修改了 `.env.prod` 里的这些内容：

- `LLM_TIMEOUT_MS`
- `LLM_API_KEY`
- `LLM_MODEL`
- `VITE_API_BASE_URL`
- `APP_PORT`

修改完成后执行：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
```

如果你已经在项目目录里，也可以直接继续用：

```bash
bash update.sh
```

但要注意：

- `update.sh` 会先执行 `git pull`
- 如果你刚在服务器上手改完 `.env.prod`，它不会覆盖 `.env.prod`
- 只要 `.env.prod` 保留在服务器上，后续更新会继续使用这份文件

## 七、常用排查命令

查看容器状态：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml ps
```

查看后端日志：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f backend
```

查看前端日志：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f frontend
```

查看数据库迁移状态：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml exec backend pnpm db:migrate:status
```

### 第一次部署线上

```bash

bash deploy.sh aliyun
```

### 线上代码更新

```bash
cd /srv/chore-tribunal
bash update.sh
```

### 线上数据库更新

```bash
cd /srv/chore-tribunal
bash update.sh
```

### 线上修改 `.env.prod` 后生效

```bash
cd /srv/chore-tribunal
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
```
