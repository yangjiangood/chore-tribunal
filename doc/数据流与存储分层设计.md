# 家庭无情裁判所 数据流与存储分层设计

## 1. 文档目标

本文档用于定义：

- 单机模式与云端模式的数据真相源
- Dexie.js 与 PostgreSQL 的职责边界
- 打卡、撤销、归档、AI 判决的数据流
- 本地缓存、离线队列、SSE 同步的协同关系

本文档是前端数据层、后端接口设计和数据库建模的共同依据。

## 2. 核心原则

## 2.1 真相源必须唯一

不同运行模式下，真相源不同：

- `单机模式`：`Dexie / IndexedDB` 是真相源
- `云端模式`：`PostgreSQL` 是真相源

## 2.2 Dexie 不只是缓存

Dexie 在本项目里承担两种角色：

### 单机模式

- 主存储
- 主查询源
- 主归档源

### 云端模式

- 本地缓存
- 最近日志缓存
- 最近标签缓存
- 待同步事件暂存
- 弱网 / 断网兜底队列

## 2.3 LocalStorage 降级为轻配置层

在采用 Dexie 后，LocalStorage 不再承载主业务数据。  
LocalStorage 仅保留轻量内容：

- 当前模式标记
- UI 偏好轻配置
- 最近登录账号
- 极小型临时标记

业务核心数据不再依赖 LocalStorage。

## 3. 存储分层总览

```text
UI 层
  ├─ 首页主屏
  ├─ 控制台
  └─ AI 判决弹窗

数据访问层
  ├─ Local Preference Store
  ├─ Dexie Repository
  ├─ API Client
  └─ SSE Client

后端层
  ├─ NestJS Services
  ├─ Redis
  └─ PostgreSQL
```

## 4. Dexie 数据域设计

## 4.1 建议表结构

前端 Dexie 建议至少包含以下表：

| 表名 | 用途 |
| --- | --- |
| `families` | 家庭基础信息缓存 |
| `members` | 成员信息缓存 |
| `taskRules` | 家务规则缓存 |
| `events` | 打卡事件 |
| `rankSnapshots` | 排行快照缓存 |
| `archives` | 周归档数据 |
| `preferences` | 本地偏好设置 |
| `pendingSyncEvents` | 待同步事件队列 |
| `verdictCache` | 最近一次或最近数次判决缓存 |

## 4.2 事件表建议字段

`events` 建议至少包含：

- `id`
- `mode`
- `familyId`
- `memberId`
- `taskType`
- `taskLabel`
- `scoreDelta`
- `createdAt`
- `status`
- `source`
- `undoExpireAt`
- `serverEventId`
- `weekId`
- `snapshot`

### status 建议枚举

- `pending`
- `confirmed`
- `reverted`
- `sync_failed`

## 5. PostgreSQL 数据域设计

## 5.1 后端核心实体

建议后端主实体至少包括：

- `Family`
- `FamilyAccount`
- `Member`
- `TaskRule`
- `TaskEvent`
- `WeeklyArchive`
- `VerdictRecord`
- `Preference`

## 5.2 关系特点

### Family

- 1 对 1 对应一个统一账号主体
- 1 对多拥有成员
- 1 对多拥有规则
- 1 对多拥有事件与归档

### TaskEvent

是业务核心事实表。

必须保存：

- 当时的成员
- 当时的标签
- 当时的分值
- 当时的分类
- 当时的事件状态

后续规则变化不能回写旧事件。

## 6. 单机模式数据流

## 6.1 初始化

```text
用户选择单机模式
  → 前端初始化 Dexie
  → 建立默认家庭数据
  → 后续所有读写都走本地
```

## 6.2 打卡流程

```text
点击成员
  → 点击档位
  → 选择标签
  → 写入 Dexie.events(status=pending)
  → 更新本地排行与日志
  → 弹出 5 秒撤销 Toast
  → 到时未撤销则转 confirmed
```

## 6.3 撤销流程

```text
用户点击撤销
  → 将事件标记为 reverted
  → 回退成员分数
  → 回退排行
  → 从公开日志移除或标记撤回
```

## 6.4 周归档流程

```text
用户触发周结算
  → 汇总 confirmed 事件
  → 生成本地周档案
  → 可选触发 AI（若模式允许）
  → 写入 archives
  → 开启新周
```

## 7. 云端模式数据流

## 7.1 初始化

```text
用户登录
  → 拉取 family / members / taskRules / current week snapshot
  → 写入 Dexie 缓存
  → 建立 SSE 连接
```

## 7.2 打卡流程

### 在线正常流程

```text
点击成员
  → 点击档位
  → 选择标签
  → 前端先乐观写入 Dexie.events(status=pending)
  → 本地更新排行与日志
  → 向后端提交 createEvent
  → 后端写 PostgreSQL
  → 返回 serverEventId / undoToken / eventStatus
  → 前端更新本地事件映射
  → SSE 向其他设备广播最新状态
```

### 关键原则

- 前端可以乐观更新
- 后端才是最终真相源
- 其他设备只认后端广播的结果

## 7.3 撤销流程

```text
用户在 5 秒内点击撤销
  → 前端立即本地回退
  → 调用 undoEvent
  → 后端将事件标记为 reverted
  → SSE 广播回退结果
  → 其他设备同步回退
```

## 7.4 弱网 / 断网兜底

如果云端模式下短暂掉线：

```text
打卡
  → 前端写入 Dexie.pendingSyncEvents
  → 本地界面给出“待同步”状态
  → 网络恢复后顺序补发
  → 服务端确认后更新正式状态
```

注意：

- 云端模式下离线补发属于增强能力
- 第一阶段可先支持“短时缓冲”
- 不建议一开始就做复杂冲突合并

## 8. SSE 数据流设计

## 8.1 为什么选 SSE

本项目的实时需求主要是：

- 排行变化
- 日志变化
- 事件状态变化

这是典型的服务端单向推送场景。  
相比 WebSocket，SSE 更轻、更容易先落地。

## 8.2 SSE 推送内容

建议至少推送：

- `scoreUpdate`
- `rankUpdate`
- `logUpdate`
- `eventStatusUpdate`
- `archiveCreated`
- `verdictGenerated`

## 8.3 前端处理原则

- 收到 SSE 后，以服务端状态刷新本地缓存
- 不直接增量拼接未知状态
- 对同一事件优先按 `serverEventId` 合并

## 9. AI 判决数据流

## 9.1 输入来源

AI 判决只基于 `confirmed` 事件计算。

不得纳入：

- `pending`
- `reverted`
- 未正式归档的撤销中事件

## 9.2 生成流程

```text
点击召唤 AI 裁判
  → 后端汇总本周 confirmed 事件
  → 读取上周归档摘要
  → 读取风格配置 styleProfile
  → 调用 OpenAI
  → 成功则写 VerdictRecord
  → 失败则返回本地降级模板
```

## 9.3 前端缓存策略

前端可将最近一次判决写入 Dexie：

- 用于再次打开弹窗
- 用于弱网下展示最近结果
- 但不替代后端正式记录

## 10. 排行与日志计算原则

## 10.1 排行

排行建议由事件表动态聚合，或由后端维护快照。

第一阶段建议：

- 单机模式：前端基于 Dexie 聚合
- 云端模式：后端返回当前周聚合结果，前端缓存

## 10.2 日志

公开日志只展示最近 N 条正式或待确认可见事件。

撤销后：

- 可直接移除
- 或标为“已撤销”

首页建议采用直接移除，保持屏幕干净。

## 11. 备份与导入导出

## 11.1 单机模式

备份导出基于 Dexie 全量数据：

- 家庭信息
- 成员
- 规则
- 事件
- 归档
- 偏好

## 11.2 云端模式

云端模式下不依赖本地全量导出作为核心恢复手段。  
本地 Dexie 只作为缓存和暂存层。

## 12. 一致性策略

## 12.1 模式区分

### 单机模式

- 强一致范围只在本地设备

### 云端模式

- 服务端最终一致
- 前端局部乐观更新

## 12.2 冲突处理

第一阶段遵循简单策略：

- 服务端事件写入按唯一事件 ID 去重
- 前端只做顺序补发，不做复杂冲突合并
- 服务端返回权威快照，前端按快照修正

## 13. 建议的前后端接口边界

| 接口 | 写入位置 | 真相源 |
| --- | --- | --- |
| 注册 / 登录 | PostgreSQL + Redis | 后端 |
| 成员配置 | PostgreSQL | 后端 |
| 规则配置 | PostgreSQL | 后端 |
| 单机模式打卡 | Dexie | 前端本地 |
| 云端模式打卡 | PostgreSQL，Dexie 仅缓存 | 后端 |
| 单机模式归档 | Dexie | 前端本地 |
| 云端模式归档 | PostgreSQL | 后端 |
| AI 判决 | VerdictRecord + 前端缓存 | 后端 |

## 14. 最终结论

本项目存储与数据流正式采用以下原则：

1. 单机模式：`Dexie` 是真相源
2. 云端模式：`PostgreSQL` 是真相源
3. `Dexie` 在云端模式下是缓存、队列和离线暂存层
4. `LocalStorage` 只保留轻配置，不承载主业务数据
5. `SSE` 负责云端模式的主屏状态广播
6. AI 判决只基于 `confirmed` 事件

后续数据库建模、接口设计、前端 service 层和本地仓储设计，都应严格遵守本文件。
